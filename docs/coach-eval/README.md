# Coach response-quality evaluation — starting artifacts (C-017)

Generated by `npm run eval:response` (see [../COACH_RESPONSE_EVAL.md](../COACH_RESPONSE_EVAL.md)). These
are the turnkey starting files for the two-reviewer run that clears the report §6 gate.

| File | What it is |
|---|---|
| `response-eval-sheet.csv` | The 60 cases (prompt · expected · scenario · auto-fail watch) with empty score columns — a human-readable worksheet. |
| `reviewer-template.json` | A blank per-reviewer scoring file. **Each reviewer copies it** to e.g. `reviewerA.json`, sets `reviewer`, and fills every `scores.<dim>` (1–5) and `autoFail` (true/false). |
| `response-eval-manifest.json` | Run metadata bound to a release: case counts, dimensions, thresholds, auto-failure rules, and the `releaseSha` these were generated against. |

## Run it (owner)

1. Produce model replies for all 60 prompts against the **real** model with an isolated key, save as
   `replies.json` (`{ "MT01": "…", … }`), then regenerate the sheet with replies + provenance:
   ```bash
   REPLIES=replies.json RELEASE_SHA=<sha> MODEL=<model> PROMPT_HASH=<hash> npm run eval:response
   ```
2. Two independent reviewers each fill a copy of `reviewer-template.json`, blind to each other.
3. Score the gate:
   ```bash
   MODE=score SHEETS=reviewerA.json,reviewerB.json npm run eval:response
   ```
   PASS requires mean ≥ 4.2, no critical dimension < 4.0, zero automatic failures, and inter-rater
   agreement ≥ 0.75. Commit the filled sheets + manifest here as the signed evidence.

> The blank sheet here is a convenience snapshot; it is safe to regenerate at any time. The reviewers'
> filled files and the model `replies.json` are the artifacts that actually close C-017.
